# Project instructions

- Read README.md and ARCHITECTURE.md before changing plans. ARCHITECTURE.md is the plan of record; update it when a decision changes.
- Yama is free. Anyone with a verified Google account may sign up (Bryan, 22 Oct 2026: open sign-up, Google only, no username/password sign-in on the server); invited accounts get the larger allowance. Keep every user's data private to them unless they share it (Bryan, 28 Oct 2026: opt-in sharing of decks by link or profile, and of the collection; see ARCHITECTURE.md, Sharing). Sharing never exposes account details, prices paid, notes, containers, proxies, plans or games. Ship no card images, mana symbol art, or rules documents; images load from Scryfall at runtime. Keep the "unofficial, not endorsed by Wizards" notice.
- Default completion (Bryan, 27 Oct 2026): carry requested repository work through a feature-branch push, PR, Codex review, fixes, a subsequent independent agent review for substantive changes, required checks and merge. This is standing authorization for those scoped pushes, PRs, review requests and merges; do not stop at a local commit or an unmonitored PR. Keep automatic Codex PR review enabled by default. If the cloud reviewer is unavailable, record the limitation and obtain an independent Codex agent review rather than silently skipping review. Use event-driven PR watching while checks or reviews are pending and resume through merge; do not treat waiting as completion. Deployments, new accounts and spending still need Bryan's request. The repo lives at github.com/bryanroscoe/yama (private, created 2026-10-18 at Bryan's request); keep it private.
- Automatic production deployment (Bryan, 28 Oct 2026): successful push CI on current main triggers the dedicated saget runner. Merging reviewed work now requests that release. Threads must not run historic deployment scripts or race the runner; current manual retries use `./deploy/deploy.sh` and the same host lock/CI gate. Read `deploy/RUNNER.md` for pause, status and recovery. Host entrypoint changes require a separate reviewed installation on saget; merging a changed host script does not install it automatically.
- Releases follow [deploy/RELEASING.md](deploy/RELEASING.md): fetch GitHub before integrating changes, merge the intended completed work into main, verify it, publish main, then deploy only from clean main matching freshly fetched origin/main. If fetching GitHub fails, stop; cached remote refs do not count as up to date. Fetch, reconcile and verify again after a rejected push; never force-push main or bypass the deployment guard. Never deploy a feature branch or detached HEAD. Preserve other threads' uncommitted work; do not bundle it into a release. `./deploy/deploy.sh --check` checks readiness without contacting saget.
- Worktrees (Bryan, 31 Oct 2026): the main checkout (~/Developer/yama) is shared and often sits on a WIP branch with other threads' uncommitted work. If your work would conflict with it (wrong branch, dirty files, another thread's changes), move into a worktree off freshly fetched origin/main instead of working around it there. In T3, `t3_worktree_handoff` moves your thread into one and `t3_thread_launch` with `workspaceStrategy` starts a new agent in one; manual worktrees go under ~/Developer/.worktrees/yama/<task>. Pass this rule to every agent you start or brief. Check free disk before installing or building in a new worktree, and retire it when the task is done.
- The Phase fork lives in the public `github.com/bryanroscoe/yama-phase` repository (public since 2026-10-31; the earlier private repository is `bryanroscoe/yama-phase-archive`). Commit to it only as `bryanroscoe@gmail.com`. Publish accepted engine changes there and pin their full SHA in `deploy/phase-rev`; `deploy/phase-repo` names the source. Keep a sibling `../yama-phase` checkout for Cargo, or set `YAMA_PHASE_DIR` for release exports. Patch exports in Yama are retired.
- Prices: a missing price stays missing (never 0). Every price carries its date and source. A Scryfall/TCGplayer market price is not a store quote or proof of availability.
- Don't copy AGPL code (e.g. CollectorVision) into this repo while it's private.
- The disk is nearly full. Keep Rust debug info low (already set in Cargo.toml), use `CARGO_BUILD_JOBS=4`, and delete large downloads after use.
- Before committing: `cargo test`, `npm test`, `npm run typecheck`.
- CI minutes are paid: keep PRs in draft until ready (drafts run no CI). On the final commit, `scripts/local-ci.sh` runs CI's checks and, only if all pass, records a `Local-CI` trailer so PR CI skips them (docs/ci.md). Never write the trailer by hand; the checks must actually pass. Push CI on main always runs in full.
- To see the site (a polish pass, checking a UI change at every size), use `npm run polish` (docs/polish.md): screenshots of every page, press and size with layout and copy checks, read-only even on production.

## Code

- Server: Rust 2024, Axum 0.8, sqlx 0.9 on SQLite. sqlx 0.9 requires `sqlx::AssertSqlSafe(..)` around SQL built at runtime; only ever interpolate constants or compiled search clauses, and bind every value.
- Offline-first writes are ops with client-generated IDs, applied idempotently (`applied_ops`, game event `seq`). Keep that property for any new sync path.
- The search grammar lives in `server/src/cards/search.rs`. If an offline copy is added to `packages/core`, keep them in step.
- Web: React 19 + Vite, plain CSS with the tokens in `web/src/styles.css`. The design is "Night table" (`design/tokens.md`, chosen 2026-10-19; felt green is retired): near-black neutral ground, commander art behind players and decks under a dark wash, white as the only accent, mana colors only to mean whose. Never filter, blur or fade a card image, and credit the artist wherever an art crop shows. Gradients only as washes over art, no all-caps labels, no middle-dot meta strings.

## Code Review Rules

- Check owner isolation at every external boundary, including worker credentials, leased inputs/results and account deletion. Safe path: bind the owner in queries, fence expired leases and remove dependent private data on account deletion.
- Keep experiment inputs and build identity explicit. Retries and comparisons must not duplicate scored games, split paired pods across builds or silently leave work impossible to claim.
- Before merge, resolve actionable review findings and verify the current head against current main. Report local tests, GitHub checks, reviews, merge and deployment as distinct evidence.
