Yama MCP

Build a Commander deck, improve one you own, or understand a tricky interaction. Connect your assistant to the same decks, collection and research tools Yama uses.

Yama hosts the MCP server. You connect to it with your own account; there is no separate Magic MCP package or card database to install. Yama is free. Your assistant's own plan and usage terms still apply.

What you can do

Build and upgrade decks

Work from your theme, budget, declared bracket and protected cards. Get exact additions and cuts, compare the lists, check Commander legality, and stage a new deck or a replacement for review. Saved versions keep the previous list.

Research cards and interactions

Search with full Scryfall syntax, inspect printings and rulings, explore EDHREC recommendations and Commander Spellbook combos, and look up current official rules with their source and effective edition.

Review complete research builds

Keep current and bracket alternatives, explained rough power, executable combos, exact swaps and dated local shopping evidence together in your private Research section. Preferred builds, swap answers and notes survive refreshed research.

Use the cards you own

Check quantities, proxies and locations; find cards outside deck boxes; estimate needed copies and dated singles costs. Propose collection additions, moves and condition updates.

Import, compare and test

Read public Moxfield and Archidekt decks, compare saved or proposed lists, sample reproducible opening hands, calculate source-draw probabilities and run bounded land-sequencing checks.

Keep upgrade plans moving

Read stock, current and planned lists, review swaps and propose ideas. Record your review answers, bought cards and installed swaps, including putting planned prints into the linked deck.

Inspect simulation evidence

Read precon benchmarks, dated editorial upgradeability assessments, your lab runs, live progress and individual games. When you request it, stage a Phase or Forge experiment, more games, a repeat or a cancellation. Lab allowances and queue limits apply.

Recommendations are suggestions grounded in the available data. Community popularity does not prove a win-rate improvement. Mana checks state their assumptions; the land-sequencing model omits ramp, fetches, filters and mulligans. Missing prices stay unknown, and market prices are not store quotes or resale offers.

Connect your assistant

First sign in to Yama with a verified Google account. Use that account when the connection opens Yama's approval page. Reading this guide does not require an account.

The hosted server address is:

https://yama.ing/mcp

This is a tool endpoint, not a page to open in a browser.

Claude Code

  1. With Claude Code installed, run this in Terminal. User scope makes Yama available across your projects: 
    claude mcp add --transport http --scope user yama https://yama.ing/mcp
  2. In Claude Code, enter /mcp, select yama and choose Authenticate.
  3. In the browser, sign in to Yama, review the requested access and press Allow. Return to Claude Code and check the connection in /mcp.

Already have a Yama connection? Reuse it. See the official Claude Code MCP instructions for client installation, scopes and connection management.

Claude on the web, desktop or phone

  1. On Claude's web or desktop app, open Customize → Connectors (called Settings → Connectors in some versions). Choose Add, then Add custom connector.
  2. Name it Yama and use https://yama.ing/mcp as the remote server URL.
  3. Use sign-in authentication. If an OAuth client choice is shown, choose Register automatically. Connect, sign in to Yama and press Allow.
  4. Enable Yama for the conversation. Once connected, it can also be used from Claude's mobile apps.

Your Claude plan or organization may control which connectors you can add. Follow the official Claude connector guide if the menus differ.

Codex

  1. With Codex CLI installed, add the hosted server: 
    codex mcp add yama --url https://yama.ing/mcp
  2. Complete the browser sign-in if it starts automatically. Otherwise run: 
    codex mcp login yama
  3. Sign in to Yama and press Allow. Run codex mcp list to check the registration, and use /mcp inside Codex to inspect the active connection.

See the official OpenAI documentation for MCP for Codex settings and other supported surfaces.

Other MCP clients and script keys

Use a client that supports Streamable HTTP and OAuth with the same server URL. If it cannot sign in, create an MCP-scoped key under Decks → Plans → Settings and follow the connection instructions shown there. Treat the key as a password. A plan-sync key cannot access MCP tools.

Inside Yama: Ask Claude already uses these tools when available for your account. No external connection is needed. Availability and allowance are shown in Yama.

Buy cards locally from your latest build

For every deck at once, open Source cards across decks under Plans → Get the cards. Choose a saved source report and all decks or a subset. Cards are grouped with quantities per recipient; bracket alternatives count as a union. Keep optional real replacements separate, select known-stock copies together, and build combined store carts. Unknown quantities need a store check. This private preview does not approve plans or change orders.

Ask your assistant to verify the exact deck configuration and latest bracket-build revision, then check your real copies, proxies, print orders and reserved copies. Real replacements for proxies are optional. A bracket label or power estimate alone does not identify a deck version.

  1. Read overview, plan_deck and the exact research build. Compare the list with your latest saved configuration before reusing an older shopping report.
  2. Read shopping_settings, shopping_list, shopping_trip and store_stock. Compare their check dates. Saving research does not itself activate a plan or refresh trip stock; an archived report may contain evidence the trip is not using. Refreshing an already tracked build can rederive its recognized offers and lists, but does not fetch fresh store stock.
  3. For a requested refresh, stage check_stores for the applicable stores and exact card names, at most 300 per check. Review the staged check before applying it. For an unapproved build, pass its cards explicitly; do not approve a plan just to see prices. The trip currently has no arbitrary research-build preview argument.
  4. Ask for direct listing links, needed and available quantities, condition, finish, dated prices and remaining unknowns. Include TCGplayer Pro stores as well as Shopify. A blocked search is unknown, not out of stock.
  5. Choose quantities and open the store cart or listing. Shopify filled-cart links replace that store's existing cart. TCGplayer Pro requires adding the confirmed variant on the listing page. Select pickup and complete checkout yourself.

Austin store examples: Black Castle Gamez in Cedar Park, Multiverse Hobbies in Hutto, Mothership and Pat's Games. Your account's store preferences and current buy rules determine your trip. Verify pickup for other regional sellers; call-only stores need a phone check.

Selling is separate: use Yama's Sell list and dated offers, or the Mothership buylist and Pat's buylist. Cash, store credit and retail prices mean different things. No research save, cart link or quote records a purchase or installation.

Assistants: read the full yama://shopping/workflow MCP resource. Return an actionable buying handoff, not only a link to archived research. If the trip does not represent the requested build, say so and provide separate preview links.

Try these requests

Use the name of a deck in your account, or paste a list. Explain your playgroup goals and anything you want to keep.

Review my Aragorn deck with a $50 upgrade budget. Prefer cards I own, keep the monarch theme and avoid infinite combos. Show exact additions, cuts, estimated costs and tradeoffs before staging changes.
Build a Commander deck around this commander and theme. Ask about my budget and playgroup first, verify the complete 100-card list, and show what I still need.
Read this public deck URL and compare it with my saved deck. Explain the differences and validate the list before proposing an import.
Explain this card interaction using Oracle text, rulings and numbered current rules. Tell me which board-state details you still need.
Show my lab run's progress and each engine's results, including uncertainty and games that were not scored.

Clients that support MCP prompts also expose review_deck, build_commander and rules_question. Ordinary requests work too.

You review changes

save_research stores private research notes directly, and review_research records a choice you state. These never install a build, approve a purchase, move inventory or promote a planner swap. Changed research evidence is flagged beside your retained answers.

Tools that edit a deck, plan, collection or lab run first create a pending proposal. Review it in Decks → Suggested changes, then choose Apply or Discard. Applying a deck edit saves a new version; stale edits are rejected if the target has changed.

Ask Claude inside Yama cannot apply its own proposals. An external MCP client also has apply and discard tools; it is instructed to apply only after you approve that exact change. Your client's permission settings control its tool calls.

Your account and research data

A connection can read your Yama decks, collection and plans; other accounts' private data is not accessible. Information returned to an external assistant is processed by that assistant's provider. Use your own account and review the access page before connecting.

Public research uses Scryfall, EDHREC, Commander Spellbook, Wizards and supported public deck hosts. EDHREC receives the public commander or theme; ownership filtering stays in Yama. Matching a private deck against Spellbook combos requires an explicit request to share its card names and quantities. It does not send your deck name, notes or collection.

Manage and disconnect OAuth connections in Plan settings → Connected apps. Revoke script keys separately on the same page. See Yama's privacy policy.

Workflow prompts and resources

Prompts: review_deck, build_commander, rules_question. Resources: yama://shopping/workflow, yama://research/sources, yama://research/format, yama://deck/{deck_id} and yama://card/{oracle_id}. Resources use the same authentication as the tools.

This is a Commander-focused toolset. Limited drafting, constructed sideboards and tournament metagame feeds are outside its current scope. Public providers may block automated access or be temporarily unavailable; failures are reported rather than treated as empty results.

If something does not connect

The endpoint shows an error in my browser
Use the address in your MCP client. A normal browser visit to /mcp is not the sign-in flow; start authentication from the client.
I see an old tool list
Reconnect the Yama server or start a new conversation. Some clients keep a catalog for the life of a conversation.
Sign-in expired or access was revoked
Authenticate again from the client. In Codex, use codex mcp login yama; in Claude Code, use /mcp. Check that you chose the Yama account containing your decks.
A proposed change will not apply
If the deck or plan changed after the proposal was made, ask the assistant to read the current version and prepare a fresh proposal.

Need help? Contact Yama. Include the client and error message, keeping tokens and private deck details out of public reports.
